## Installing a release binary

Download the archive for your system from the
[Releases page](https://github.com/emmaglorypraise/ObsidianLog/releases)
(under **Assets**, on the latest release). Not sure which file you need?
See the [FAQ](/get-started/faq). Each archive contains two binaries
directly: `obsidianlog` (the CLI) and `obsidianlog-ingest` (the standalone
ingest server). There's no installer and no dependencies to install
separately.

Whether extracting it lands those two files in their own folder depends
on how you extract it. Double-clicking the archive (or your file manager's
Extract option) creates a new folder named after it automatically.
Extracting from a raw `tar` command doesn't, it dumps the files into
whatever directory you're already in. The commands below account for
both, so you end up in a tidy folder either way.

<Tabs>
  <Tab title="macOS / Linux">
    Double-click the downloaded `.tar.gz` file (or use your file manager's
    **Extract** option). It extracts into a new folder named after the
    archive. Open that folder, open a terminal there, and run:
    ```sh
    chmod +x obsidianlog obsidianlog-ingest
    ./obsidianlog init
    ```
    On macOS, the quickest way to open the right folder in Terminal: open
    Terminal, type `cd ` (including the space), then drag the extracted
    folder from Finder into the Terminal window and press Enter.

    Prefer to do the extraction from a terminal too?
    ```sh
    cd ~/Downloads
    mkdir obsidianlog-<version>-<target>
    tar -xzf obsidianlog-<version>-<target>.tar.gz -C obsidianlog-<version>-<target>
    cd obsidianlog-<version>-<target>
    chmod +x obsidianlog obsidianlog-ingest
    ./obsidianlog init
    ```
  </Tab>
  <Tab title="Windows">
    Right-click the downloaded `.zip` file in File Explorer and choose
    **Extract All**. It suggests a new folder named after the archive,
    accept the default. Open that folder, open PowerShell there
    (Shift + right-click → **Open PowerShell window here**, or right-click
    → **Open in Terminal**), and run:
    ```powershell
    .\obsidianlog.exe init
    ```
    No `chmod` step needed, `.exe` files are already executable. Prefer
    PowerShell for the extraction too?
    ```powershell
    cd ~\Downloads
    mkdir obsidianlog-<version>-x86_64-pc-windows-msvc
    Expand-Archive obsidianlog-<version>-x86_64-pc-windows-msvc.zip -DestinationPath obsidianlog-<version>-x86_64-pc-windows-msvc
    cd obsidianlog-<version>-x86_64-pc-windows-msvc
    .\obsidianlog.exe init
    ```
  </Tab>
</Tabs>

The exact filename depends on which release and target you downloaded,
matching what you got from the Releases page. The `chmod` step on
macOS/Linux is needed because the executable bit isn't always preserved
inside the archive.

<Note>
`obsidianlog` is a command-line tool, not a GUI app. The commands above need
an actual terminal (Terminal on macOS, PowerShell or Windows Terminal on
Windows, your terminal app on Linux). Double-clicking the binary itself
does **not** start setup: it has no command to run, so it prints the help
screen and exits. Open a terminal, change into the extracted folder, then
run `./obsidianlog init` (or `.\obsidianlog.exe init` on Windows).
</Note>

The first time you run it, your OS may flag it as unsigned, since these
binaries aren't code-signed today:

<Tabs>
  <Tab title="macOS">
    Gatekeeper blocks it. The most reliable fix, especially for these
    command-line binaries, is to clear the quarantine flag directly in a
    terminal:
    ```sh
    xattr -d com.apple.quarantine obsidianlog obsidianlog-ingest
    ```
    Prefer the GUI instead? The order matters here: right-click
    `obsidianlog` in Finder and choose **Open** once (this attempt gets
    blocked, that's expected, it's what registers the binary with macOS).
    *Then* go to **System Settings → Privacy & Security**, scroll to the
    Security section, and click **Open Anyway** next to the message naming
    `obsidianlog`. That button only appears after a blocked attempt, not
    before, so doing this step first won't show it.
  </Tab>
  <Tab title="Windows">
    SmartScreen shows "Windows protected your PC." Click **More info**,
    then **Run anyway**.
  </Tab>
  <Tab title="Linux">
    There's no equivalent prompt. As long as `chmod +x` was run, it just
    works.
  </Tab>
</Tabs>

## Archive your first log and get it back

The CLI wraps setup, ingestion, retrieval, and integrity checking. These
four steps take under a minute and use `--non-interactive`, which always
picks the local backend and skips every setup question, the fastest way to
see the whole loop work. Omit that flag if you'd rather answer each
question yourself.

<Tabs>
  <Tab title="macOS / Linux">
    Two terminals, both open in the folder you extracted. Leave the first
    running `serve`; use the second for everything else.

    **1. Set up.** Generates the encryption key and writes `config.toml`.
    ```sh
    ./obsidianlog init --non-interactive
    ```
    You'll see:
    ```text
    obsidianlog initialized.
      config:      /Users/you/.config/obsidianlog/config.toml
      credentials: the OS keychain
    ```

    **2. Start the server.**
    ```sh
    ./obsidianlog serve
    ```
    The terminal won't return to a prompt after this, it keeps running
    until you stop it. That's expected, leave it running and use your
    second terminal for the rest.

    **3. In the second terminal, send a log.**
    ```sh
    curl -s -X POST http://localhost:7080/ingest \
      -H 'content-type: application/json' \
      -d '[{"timestamp":"2026-07-06T10:00:00Z","service":"api","level":"info","msg":"hello"}]' \
      -w '%{http_code}\n'
    ```
    A successful ingest has an empty body, so the `200` printed on its own
    line (from `-w`) is the actual confirmation, not the absence of output.

    **4. Query it back.**
    ```sh
    ./obsidianlog query --service api --level info --from 24h --format human
    ```
    ```text
    2026-07-06T10:00:00Z  api  info  -  hello
    ```

    **5. Verify the hash chain.**
    ```sh
    ./obsidianlog verify
    ```
    ```text
    OK   api: 1 chunk(s) verified, chain intact
    ```
  </Tab>
  <Tab title="Windows">
    Two PowerShell windows, both open in the folder you extracted. Leave
    the first running `serve`; use the second for everything else.

    On some machines, PowerShell doesn't set the environment variable
    ObsidianLog looks for by default. Set it once per window, then every
    command below works exactly like the macOS/Linux commands, no
    `--config` needed:
    ```powershell
    $env:HOME = $env:USERPROFILE
    ```

    **1. Set up.**
    ```powershell
    .\obsidianlog.exe init --non-interactive
    ```
    You'll see:
    ```text
    obsidianlog initialized.
      config:      C:\Users\you\.config\obsidianlog\config.toml
      credentials: the OS keychain
    ```

    **2. Start the server.**
    ```powershell
    .\obsidianlog.exe serve
    ```
    The terminal won't return to a prompt after this, it keeps running
    until you stop it. That's expected, leave it running and use your
    second terminal for the rest.

    **3. In the second terminal, run `$env:HOME = $env:USERPROFILE`
    again first (it's per-window, not sitewide), then send a log.**
    Assign the JSON to a variable first, PowerShell's quoting breaks on a
    curl command written the Unix way:
    ```powershell
    $json = '[{"timestamp":"2026-07-06T10:00:00Z","service":"api","level":"info","msg":"hello"}]'
    curl.exe -s -X POST http://localhost:7080/ingest -H "content-type: application/json" -d $json -w "%{http_code}\n"
    ```
    A successful ingest has an empty body, so the `200` printed on its own
    line (from `-w`) is the actual confirmation, not the absence of output.

    **4. Query it back.**
    ```powershell
    .\obsidianlog.exe query --service api --level info --from 24h --format human
    ```
    ```text
    2026-07-06T10:00:00Z  api  info  -  hello
    ```

    **5. Verify the hash chain.**
    ```powershell
    .\obsidianlog.exe verify
    ```
    ```text
    OK   api: 1 chunk(s) verified, chain intact
    ```
  </Tab>
</Tabs>

See the full [CLI reference](/cli/overview) for every command's flags.

<Note>
On macOS, `init` will prompt at most once for your login-keychain password.
This is the OS asking permission for `obsidianlog` to store the credentials
it just generated, not an ObsidianLog password. Click **Always Allow**
rather than just Allow, so later `serve`/`query`/`verify` runs read them
without prompting again.
</Note>

You've now archived a real log, encrypted and hash-chained, and gotten it
back out again, the same loop a production deployment runs continuously.
